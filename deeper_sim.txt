## 1. Global Principles

1. **Single funnel**: All three match entry points must converge on one shared post-processing pipeline `simulation.finalize_match_result(match, result)` that applies: score/scorers/ratings, discipline accrual, injuries, fitness deltas, morale, cup advancement, manager records. Never duplicate this logic per engine.
2. **Server-side authority**: every rule is validated server-side in services/engine code, never only in templates or JS.
3. **One validation source**: a single `services/rules_engine.py` is the only place rule logic lives. Routes, live engine, and bulk sim all call it.
4. **Deterministic where needed**: every engine accepts a seeded RNG (`random.Random(seed)`, seed derived from `match.id * 100000 + season * 100 + day`) so results are reproducible in tests.
5. **No hidden bonuses for or against the player's team.** AI uses the same public data, same rules, same engines.

## 3. FEATURE B — Full Tactical System (FM-style, fully effective)

### B.1 Data model

Replace/extend the current tactic fields with a single JSON on Team: `Team.tactics_data`:

```json
{
  "formation": "4-2-3-1",
  "mentality": 3,                       // 1..5 (Very Defensive .. Very Attacking)
  "slots": [
    {"slot": "DMr", "player_id": 12, "role": "BWM", "duty": "S", "pi": ["press_more"]}
  ],
  "in_possession": {
    "width": "standard", "passing_directness": "standard", "tempo": "standard",
    "play_out_of_defence": false, "work_ball_into_box": true, "crosses": "mixed",
    "be_more_expressive": false, "overlap_left": false, "overlap_right": false
  },
  "out_of_possession": {
    "defensive_line": "standard",       // much_lower..much_higher (5 steps)
    "engagement": "standard",           // low_block | standard | high_press
    "pressing_intensity": 2,            // 1..4
    "press_trap": "inside",             // inside | outside | none
    "tackling": "normal",               // cautious | normal | aggressive
    "offside_trap": false, "counterpress": false
  },
  "transitions": { "counter_attack": true, "time_wasting": "normal",
                   "gk_distribution": "short" },
  "set_pieces": { "corner_l": null, "corner_r": null, "fk": null, "pen": null,
                  "att_routine": "mixed", "def_routine": "zonal" }
}
```

- Migrate: on first load, any team without `tactics_data` gets a default built from its existing `pressing_style` + `match_tactic` + `formation_data` (bootstrap function like the cups bootstrap). Old columns remain and stay in sync for backward compatibility.
- Extend the existing `TacticPreset` to store full `tactics_data` snapshots (keep load/save/delete endpoints, extend payloads).

### B.2 Role library (`config/roles.py`)

Define ≥ 22 roles across lines, each with: allowed positions, allowed duties, and numeric modifier dict. Examples (not exhaustive): `SK, CD, BPD, NCB, FB, WB, CWB, DM, Anchor, BWM, REG, VOL, CM, AP, MEZ, BBM, CAR, AM, SS, W, IF, IW, DW, TM, AF, DLF, P, F9`.
Each role modifier affects derived profile keys, e.g. `BWM: {pressing:+2, tackling:+2, creativity:-1, positioning:+1}`, `AF: {movement:+2, finishing:+1, defensive_work:-2}`.

### B.3 Player instructions (PIs)

Curated catalogue per position group (`config/roles.py::PI_CATALOG`): stay_wider, cut_inside, hug_touchline, roam, hold_position, stay_back, get_forward, press_more, press_less, tackle_harder, ease_off, mark_tighter, move_into_channels, come_deep, run_in_behind. Max 3 PIs per player. Each PI maps to the same derived-profile keys.

### B.4 Derived team profile (the bridge to simulation)

`services/tactics.py::derive_team_profile(team, players) -> TeamProfile` — a pure function computing, from XI abilities + roles + duties + PIs + instructions + familiarity:

```
attack_eff, defense_eff, possession_base, chance_quality, aerial_threat,
counter_threat, press_resistance, press_fatigue_mult (1.0..2.2),
foul_rate_mult, offside_risk, set_piece_threat, gk_exposure
```

Publish a documented mapping table (put it as a docstring) — e.g. higher defensive line → higher offside_risk + higher through-ball vulnerability + more space won; pressing_intensity → opponent pass accuracy down, own fatigue up; aggressive tackling → duels won up + cards up; long directness + TM → possession down + aerial_threat up; counterpress → regain chance up + defensive gap chance up. **Every engine (L1/L2/L3) consumes TeamProfile — this is what makes tactics "فعالة بالكامل" in match-by-match AND bulk sim.**

### B.5 Tactical familiarity

- `Team.tactical_familiarity` (0–100) + `Team.tactic_fingerprint` (hash of tactics_data key settings).
- Grows per match played with the same fingerprint (+8 per L1 match, +4 L2, +2 L3) up to 100; drops to 40 on fingerprint change. Effect: at low familiarity add execution noise and scale down positive modifiers (mult = 0.5 + familiarity/200). Show a meter in the UI.
- Keep quick-preset behavior: `pressing_style`/`match_tactic` endpoints map onto the new structure so old saves and old UI don't break.

### B.6 Set pieces

Takers (corner L/R, FK, pen) are used by L1 engine for set-piece events; routines bias set_piece_threat. If no taker chosen → automatic pick by relevant attribute (existing penalty/freekick taker fields remain as fallback).

### B.7 API & UI

- New `routes/tactics_routes.py` + `templates/tactics.html`: pitch canvas (reuse/extend the existing formation editor), role+duty picker per slot, PI picker, instruction accordions (In Possession / Out of Possession / Transitions), mentality slider, set pieces tab, familiarity meter, presets row.
- All saves validated server-side (positions must be filled by eligible registered players; `validate_starting_xi` runs on save).

## 4. FEATURE C — Three Simulation Levels + World Simulation

### C.1 Engine contract

Create `simulation/engines/` with one interface:

```python
simulate(match, home_profile, away_profile, rng) -> MatchResult
# MatchResult: score, scorers[], assists[], cards[], injuries[], ratings{},
#              fitness_deltas{}, events[] (L1 rich / L2 light / L3 empty), stats{}
```

All engines route their result through `finalize_match_result` (section 1). XIs always come from `auto_pick_xi` / validated user XI (section A.3).

### C.2 Level 1 — Full minute-by-minute (user's division)

- Extract the existing live engine's core into a reusable headless mode (`live_match` logic parameterized: `mode="live"` vs `mode="headless"`) so `run_auto_match` and live matches share one engine — no divergent duplicate.
- Consumes: full TeamProfile (roles, PIs, instructions, familiarity), fitness, morale, form, home advantage, set-piece takers, in-match AI decisions (section D.4), weather-free but include momentum.
- Produces: full events, ratings, cards, injuries, subs, fitness drain scaled by `press_fatigue_mult` and duties.
- Budget: ≤ 120 ms per headless match.

### C.3 Level 2 — Medium (same tier, other leagues)

- `engine_l2.py`: possession-weighted aggregate model. Compute both TeamProfiles, derive expected goals for each side (attack_eff vs defense_eff, chance_quality, possession_base, home advantage), then sample a short list of 6–12 "key moments" (goal chances, 1–3 cards, 0–1 injury) from that xG. Scorers weighted by role/duty (AF > IF > CM...). Applies discipline/fitness through the shared funnel. Tactics still matter (they change the xG inputs).
- Budget: ≤ 3 ms per match.

### C.4 Level 3 — Superficial (higher & lower tiers)

- `engine_l3.py`: strength-differential statistical model — `attack_strength`/`defense_strength` from squad average rating + form + morale, λ_home / λ_away → Poisson (or negative binomial) score sample. Scorers picked from attackers weighted by rating. Cards: only rare random yellows into the same discipline counters. **Must visibly respect strength gaps**: a Tier-1 giant vs a Tier-4 minnow produces realistic scorelines (test-documented).
- Budget: ≤ 0.3 ms per match.

### C.5 Routing (`simulation/levels.py`)

```python
def get_sim_level(match, user_league) -> 1|2|3:
    # Any match involving the player's club -> 1 (user plays it live; "instant result" = L1 headless)
    # Both clubs from the user's league            -> 1 (headless)
    # Both clubs from the user's tier (other leagues, cup ties, continental) -> 2
    # Anything involving clubs from higher/lower tiers -> 3
```

Match report page shows an engine badge (محاكاة كاملة / متوسطة / سريعة).

### C.6 World simulation

- `simulation/world.py::simulate_world_week(state)`: advances **every** competition for the current week — all leagues (L1/L2/L3 by routing), cups on `CUP_MATCH_WEEK`, continental rounds on their designated weeks — updating tables, stats, discipline, fitness, finances for the whole world in one pass.
- Wire it into: `/continue`, `/advance_week`, `/simulate_to_date` (replace per-league-only behavior with world-wide), plus a new "محاكاة العالم" button + `routes/world_routes.py` + `templates/world.html` (world overview: tiers, per-league leaders, engine-level badges, bulk progress bar using the existing `background=True` pattern).
- Ensure `start_new_season` generates fixtures for **all** leagues with the same week grid so lockstep world weeks work (audit and fix if any league lacks a fixture list).
- Non-player leagues' AI teams get results and consequences (tables, promotion race, continental qualification) — the world must feel alive when the user reaches it via promotion/relegation.

### C.7 Performance requirements

- A full world week (all leagues + cups) ≤ 5 s typical; `simulate_to_date` chunks commits (~200 matches per commit) and streams progress; use `joinedload` to avoid N+1 on squads; L3 must not touch more than squad-aggregates (no per-player loops beyond scorer pick).

## 5. FEATURE D — Competent-but-Beatable AI

### D.1 Personas

`ai/persona.py`: each AI team gets a stored profile `Team.ai_profile` JSON: `archetype` (pragmatist / attacker / defensive / tinkerer / youth_lover), `skill` (0.35–0.85; mean rises with tier but with wide variance), `patience`, `ambition`, `transfer_aggression`, `risk_tolerance`. Never regenerate mid-save; assign at season start for teams missing one.

### D.2 Weekly planner (`ai/planner.py`)

Runs inside day/week advancement for every AI club: review board objectives, budget health, squad needs, fixture difficulty; choose tactic (from its own presets + persona) for the next match with a **mistake probability** `(1 - skill) * 0.35` (picks the counter-tactic vs opponent's strengths otherwise).

### D.3 Transfer AI (`ai/transfer_ai.py`)

- Needs assessment vs its formation → prioritized shopping list. Valuation = f(overall, age, contract) ± 15 % noise; max bid capped at `valuation * (1 + 0.25*skill)` and at 80 % of its transfer budget (reserve rule).
- Selling: accepts offers ≥ valuation×1.1 (key players) / ×0.9 (fringe); lists surplus; always keeps ≥16 players and 2 GKs (rules engine enforces anyway).
- **Beatability mechanics (required)**: 1–3 day reaction delay before acting on a listing; never more than 2 AI bidders on the same player; occasionally (skill-scaled) overpays or undervalues (e.g., undervalues veterans, overrates pace); walks away after 2 counters. The user can consistently out-negotiate a low-`skill` AI and find value the AI misses.
- AI↔AI transfers run silently in background during windows.

### D.4 In-match AI (`ai/match_ai.py`)

For AI-controlled sides **inside L1 matches** (user's matches and headless L1), act at fixed checkpoints only — HT, 60', 75' — plus forced events (injury, red card):
- Losing → mentality +1 step (bounded), sub lowest-rated (< 6.2) or fitness < 50 if subs remain.
- Winning by 2+ after 70' → time_wasting up, defensive_line down one step.
- Red card → immediate defensive reshuffle, sacrifice an attacker.
- All changes pass through the same tactics/roles validation and sub rules.
- **Beatability**: checkpoints only (no per-minute optimal adaptation), each decision has a `(1-skill)` chance to pick the persona-consistent-but-suboptimal option; low-skill AI ignores bait (e.g., keeps high line against a pacy counter) — high-skill AI adapts. No rubber-banding, no stat boosts.

### D.5 Budget & board AI

Split budget transfer/wage by squad state; if wage bill > projected income → sell top earner; invest surplus in facilities/training via the existing facility system; request board funds after overperformance (hooks into existing `BoardObjective`).

### D.6 Difficulty setting

`GameState.ai_difficulty` (سهل/عادي/صعب, default عادي): scales the skill mean and reaction delays only — never adds hidden modifiers to AI teams' players. Expose in setup and dashboard.
